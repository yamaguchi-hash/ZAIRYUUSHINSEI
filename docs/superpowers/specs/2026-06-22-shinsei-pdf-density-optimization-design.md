# 申請書PDF（一括）の余白ゼロ化・枚数最小化・ロール分離 設計書

- 作成日: 2026-06-22
- 対象: 在留申請システム（zairyu-shinsei-system）
- ブランチ: feature/pdf-split-and-org-master
- 対象ファイル: `src/app/print/[id]/shinsei/page.tsx`（「申請書PDF（一括）」、`/print/[id]/shinsei` ルート）のみ

## 背景・現状調査の要点

申請案件詳細の「申請書作成」画面（[shinsei-form/page.tsx](<src/app/(dashboard)/applications/[id]/shinsei-form/page.tsx>)）には3つのPDF出力ボタンが存在する。

1. **「申請書PDF（一括）」** — `/print/[id]/shinsei`（`shinsei/page.tsx`、約1615行）。申請人用・所属機関用・扶養者用を1つのPDFに統合し、`page-break-before:always` でセクション単位の強制改ページを行う。COE/変更/更新・全カテゴリ（N/T/R/P/V）の出し分けが完備した、現状唯一の完全な実装。
2. **「申請人用PDF」** — `/print/[id]/shinsei-applicant`。共通基盤 `shinsei-shared.tsx` を使用し、既に印刷余白7mm/9mm・連続フロー方式で最適化済みだが、formType（COE/変更/更新/永住）やカテゴリ（N/T/R/P）別のPart2内容が未実装（常に「変更」固有項目を表示）。扶養者（R型）用セクションも存在しない。
3. **「所属機関用PDF」** — `/print/[id]/shinsei-org`。同基盤を使用し、所属機関ロールのみ最適化済み。

調査の結果、**「申請人用PDF」「所属機関用PDF」は未完成の途中実装**であり、本対応はユーザーの判断により**「申請書PDF（一括）」（`shinsei/page.tsx`）のみ**を対象とする。他の2ルートおよび共通基盤 `shinsei-shared.tsx` は変更しない。

### 発見した技術的課題

`shinsei/page.tsx` の現行CSSは次のようになっている。

```css
@page{size:210mm 297mm;margin:0;}
.page{padding:14mm 16mm;...}
@media print{.page{padding:10mm 13mm;...}}
```

`@page{margin:0}` としたうえで、内容を囲む`.page`要素（ファイル全体で1個だけ存在し、内部の改ページはこの1要素の中で発生する）の`padding`で余白を表現している。CSSの仕様上、`padding`は要素全体に対して一度だけ適用され、ページ分割（自然な改ページ・`page-break-before`による強制改ページのいずれも）の際に複製されない。そのため、**1ページ目以降のすべてのページで、上下左右の余白が実質ゼロになっている可能性が高い**（プリンタの印字不可領域によっては内容が欠落するリスクがある）。

これは `shinsei-shared.tsx` で既に正しく実装されている `@page{margin:Xmm Ymm}` 方式（ページボックス自体に余白を持たせるため、自動生成されるすべての物理ページに適用される）とは異なる。本対応でこの実装方式を `shinsei-shared.tsx` 方式に統一し、修正する。

## 改ページ戦略

現状、ファイル内の`.section.page-break`（`page-break-before:always`）は以下のように、ロール内部の細かいセクション境目にも適用されている。

- 申請人等作成用 Part 1 → Part 2（N/T/R/P/V型それぞれ）
- V型のPart2内 ページ2 → ページ3
- 所属機関等作成用 Part 1 → Part 2（派遣先等）
- 所属機関等作成用 V1 → V2 → V3 → V4 → V5（5分割）
- R型: 申請人用２R → 扶養者用１R
- 資格外活動許可申請書（別の様式として独立）

これを次のように変更する。

- **強制改ページを残すのは、トップレベルの3ロール境目のみ**: 「所属機関等作成用」の開始時、「扶養者等作成用」の開始時（R型のみ）。「資格外活動許可申請書」は別様式として元々の強制改ページを維持する。
- 上記以外（Part1→Part2、V型の各ページ番号、所属機関等作成用V1〜V5の各セクション）は強制改ページを撤廃し、連続フローに変更する。内容が十分に収まる場合は同じページに収まり、枚数が自然に減る。
- 各`<tr>`には既存どおり`break-inside:avoid`（`page-break-inside:avoid`）を維持し、行の途中分断のみ防止する。
- `.section`/`.section2`/`.section3`の見出しには`break-after:avoid`（`page-break-after:avoid`）を追加し、見出しだけがページ末尾に孤立し直後の内容が次ページに送られる事態を防ぐ。

## 余白・密度の最適化

`shinsei-shared.tsx`で既に本番投入・検証済みの印刷時スタイルに整合させる。

| 項目 | 現状（shinsei/page.tsx） | 変更後 |
|---|---|---|
| `@page` margin | `0`（`.page`のpaddingで代替） | `6mm 8mm` |
| `.page` padding（印刷時） | `10mm 13mm` | `0`（`@page`のmarginに委譲） |
| body font-size（印刷時） | 指定なし（画面と同じ11px） | `8.5px` |
| 行間（body, 印刷時） | 指定なし（画面と同じ1.5） | `1.1` |
| `td,th` font-size/line-height（印刷時） | 指定なし（画面と同じ10.5px/1.45） | `8.5px`〜`9px` / `1.1` |
| `td,th` padding（印刷時） | 指定なし（画面と同じ4px 8px） | `1.5px 4px` |
| `.bilingual`（英語併記）font-size | 既存値を確認し圧縮 | `6.5px`〜`7px` |
| `.section`/`.section2`/`.section3` margin | `14px 0 5px` 等 | `3px 0 2px` 程度に圧縮 |
| 理由欄等の`minHeight` | `48px` | `24px`程度に圧縮 |

## ロール識別ヘッダー

各ロール開始ページの先頭（強制改ページ直後）に、コンパクトな識別バナーを追加する。

- 所属機関等作成用の開始: 「【所属機関用】」
- 扶養者等作成用の開始（R型）: 「【扶養者用】」

既存の`.section.page-break`見出し（例:「所属機関等作成用　Part 1 N　— 機関情報・雇用条件」）の直前に、新規の小さな識別バナー要素として追加する。申請人等作成用は文書の先頭（1ページ目）から始まるため、識別バナーは付与しない（既存の様式タイトル・Part表記で十分識別可能なため）。

## 横並び圧縮

ファイル内のテーブルは大半が既に「ラベル＋値」を2組横並びにした4列構成になっており、大規模な再構築は不要と判断した。以下のような、1項目のみで行を占有している箇所を中心に、見つかった範囲でペア化する。

- 所属機関の「所在地（主たる勤務場所）」（`colSpan={3}`の単独行）の直後に独立した「電話番号」行がある箇所（N型 Part1, V型所属機関情報など）→ 同一行に収める、もしくは隙間を最小化する
- その他、調査時に発見した同様の単独行

大量にある既存の2列ペア構成のテーブル自体は変更しない。

## テスト方針

- `npm run build`でTypeScriptエラーがないことを確認
- 実際の案件データ（COE/変更/更新×N/T/R/P/V型の組み合わせ）でPDFを生成し、以下を確認する
  - 「申請人等作成用」「所属機関等作成用」「扶養者等作成用」（R型のみ）が、強制改ページで正しく分離されていること
  - 各ロール開始ページに識別バナーが表示されること
  - ロール内部（Part1→Part2等）では強制改ページが発生せず、内容に応じて自然に詰まること
  - ブラウザの印刷プレビューで、1ページ目以外も上下左右に均等な余白があること（`@page margin`修正の確認）
  - テーブル行が途中で分断されていないこと（`break-inside:avoid`の確認）
  - 変更前と比較して総ページ数が減っていること

## スコープ外

- `shinsei-applicant`/`shinsei-org`/`shinsei-shared.tsx`の変更（別途、formType/カテゴリ別Part2の実装完了が必要な、独立した課題として扱う）
- 所属機関の署名欄（現状は空欄のみ）への会社名・代表者名の自動記名（`shinsei-shared.tsx`の`SignatureSection`が持つ機能だが、本対応のスコープである余白・枚数・ロール分離とは無関係なため対象外）
- フォントサイズの単位を`pt`へ変更すること（既存コードベースは全面的に`px`単位のため、視認性を保てる最小サイズという方針のもとpx単位のまま圧縮する）
